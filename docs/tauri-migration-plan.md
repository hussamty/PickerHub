# خطة نقل PickerHub إلى Tauri وRust

هذه الخطة تنقل واجهة PickerHub من C# وAvalonia إلى Tauri 2. Rust تصبح البنية الخلفية الوحيدة للنظام، والواجهة تُبنى بتقنيات الويب: HTML وCSS وTailwind CSS 4 وTypeScript. الهدف أن يبقى التطبيق هو نفسه في نظر المستخدم، أي الهوية والصفحات والبيانات، وأن يصبح أسرع وأصغر وأسهل في التطوير.

الخطة مبنية على قراءة الكود الحالي في الإصدار 1.2.0، وعلى نموذجين تجريبيين بُنيا وقيسا على جهاز التطوير:
- `prototypes/iced-arabic`: واجهة Rust أصلية بمكتبة iced 0.14.
- `prototypes/tauri-arabic`: الشاشة نفسها بـ Tauri 2، موصولة بنواة PickerHub الحقيقية.

## 1. الملخص والقرار

**القرار:** يُنقل التطبيق إلى Tauri 2 على مراحل:
- **البنية الخلفية:** Rust بالكامل. تشمل النواة الحالية، والتخزين، والتقاط الشاشة، والاختصارات العامة، والحافظة، والنوافذ.
- **الواجهة:** صفحات ويب تعمل داخل WebView النظام، مكتوبة بـ TypeScript وTailwind CSS 4.

**لماذا Tauri وليس واجهة Rust أصلية:**
- **العربية:** في نموذج iced ظهرت ثلاثة أخطاء في العربية، واحتاج أحدها تعديل كود المكتبة نفسها:
  - المحاذاة لليمين تُطبَّق مرتين.
  - التحديد يختفي في النص العربي.
  - النقاط تحت الحروف تُقص في حقول الإدخال.

  في Tauri عملت الأمور التالية من أول مرة دون أي تعديل: الاتجاه من اليمين لليسار، والتشكيل، والتحديد، والتفاف النص، والخلط بين العربية والإنجليزية.
- **الزجاج والحركة:** تمويه `backdrop-filter` والتحويلات ثلاثية الأبعاد وحركات CSS تغطي هوية PickerHub بكود أقل من نظام الرسم المخصص الحالي في Avalonia وSkia.
- **الحجم:** الملف التنفيذي لنموذج Tauri **4.9 ميغابايت**، مقابل **103 ميغابايت** للنسخة المثبتة حاليًا في `/opt/pickerhub`. السبب أن Tauri يستخدم WebView النظام ولا يضمّن بيئة .NET.
- **لغة خلفية واحدة:** يختفي الجسر الحالي بين C# وRust، أي JSON عبر واجهة C ومخازن محلية لكل خيط. تصبح الاستدعاءات أوامر Tauri بأنواع محددة.

**ما لا يتغير:**
- **البيانات:** ملف `workspace.json` بالمخطط 2، وملف `daily_palette_state.json`، والنسخ الاحتياطية. كلها تبقى بصيغها ومجلدها نفسه.
- **الهوية البصرية:** ألوان TrineHub، والخطان، والتميمة، والمظهران الداكن والفاتح.
- **السلوك:** العربية أولًا، والعمل دون اتصال، وعدم جمع أي بيانات عن المستخدم.

**تقدير المدة:** نحو **16 إلى 20 أسبوعًا** لمطوّر واحد متفرغ حتى إصدار بيتا يطابق الإصدار 1.2.0 في الوظائف، ثم فترة تشغيل متوازٍ قبل الإيقاف النهائي لنسخة C#. التفاصيل في [مراحل التنفيذ](#8-مراحل-التنفيذ).

## 4. البنية الخلفية بـ Rust

### 4.1 مبادئ عامة

- **منطق النطاق كله في Rust.** الواجهة تعرض البيانات وترسل نية المستخدم، ولا تحسب الألوان ولا تحفظ الملفات. هذا امتداد لما بدأته باقة اليوم.
- **أوامر قليلة غنية بدل كثيرة فقيرة.** في النموذج كان تحريك شريط اللون يرسل ثمانية استدعاءات في كل خطوة، فدُمجت في استدعاء واحد `palette` يعيد كل ما تحتاجه الشاشة.
- **لا عمل ثقيل على الخيط الرئيسي.** استخراج ألوان الصور وفك ترميزها والكتابة على القرص تتم في `tauri::async_runtime::spawn_blocking` مع إمكانية الإلغاء.
- **نوع خطأ واحد** قابل للتحويل إلى JSON وبرمز ثابت، مثل `{ code: "image_too_large", ... }`. الواجهة تترجم الرمز إلى رسالة بلغة المستخدم.

### 4.3 الحالة والتخزين (`crates/store`)

- **ملكية الحالة:** ‏`Workspace` واحد داخل `Mutex` يملكه Rust، ويُدار عبر `tauri::State`.
- **كاتب متسلسل:** تنتقل منطق `WorkspaceWriter.cs` كما هو، أي مهمة كتابة واحدة تستقبل لقطات ثابتة وتدمج الدفعات المتقاربة. `flush` هي نقطة الحفظ المضمونة عند الإغلاق.
- **الكتابة الذرية:**
  1. كتابة ملف مؤقت.
  2. `fsync`.
  3. نقله فوق القديم.
  4. الإبقاء على `.bak`.
- **القفل:** ملف قفل عبر `fd-lock`، وتتولى إضافة `single-instance` إعادة تنشيط النافذة الأولى.
- **المخطط:** نفس صيغة JSON بأسماء camelCase، عبر `serde` بخاصية `rename_all = "camelCase"`. يُضاف `#[serde(default)]` لكل حقل لتبقى الملفات القديمة صالحة. ويُرفض أي `version` أعلى من المدعوم كما يحدث الآن.
- **الترحيل:** تُنقل `RefreshAutomaticNames` ومنطق `NameScheme` إلى Rust، وتستخدم جدول `previous` الموجود في النواة.
- **النسخ الاحتياطي:** صيغة الحزمة الحالية نفسها (المكتبة مع حالة باقة اليوم)، وسجل الاستعادة نفسه.

### 4.4 الالتقاط (`crates/capture`)

| النظام | التنفيذ بـ Rust | ملاحظات |
|---|---|---|
| Windows | حزمة `windows` لـ GDI (`BitBlt` و`GetPixel`) والخطافات (`SetWindowsHookExW`) | نقل مباشر لـ `windows.c` |
| Linux/X11 | ‏`x11rb` لاستدعاءات `GetImage` و`GrabPointer` و`GrabKeyboard` | نقل `x11.c`. يُحترم ترتيب اكتشاف نوع الجلسة الموجود في `Picker.cs` |
| Linux/Wayland | ‏`ashpd` للبوابات (`PickColor` و`ScreenCast` و`GlobalShortcuts`)، و`zbus` لإضافة GNOME، و`pipewire` لقراءة الإطارات | يحل محل `Tmds.DBus` وGStreamer. قراءة PipeWire مباشرة تلغي الاعتماد على GStreamer |
| macOS | ‏`objc2-app-kit` لـ `NSColorSampler` على الخيط الرئيسي عبر `run_on_main_thread` | نقل `Picker.cs` |

**العدسة المكبرة على Windows وX11:**
- نافذة Tauri ثانية شفافة بلا إطار، فوق كل النوافذ، ولا تلتقط الفأرة إلا عند الحاجة.
- يُرسل Rust رقعة البكسلات (مثلًا 15×15) في كل إطار عبر `tauri::ipc::Channel`، وترسمها الواجهة في `<canvas>`.
- الأسهم وعجلة الفأرة وEsc تُلتقط في Rust ما دامت الخطافات قائمة، كما في الوضع الحالي.

**على Wayland:**
- يبقى المسار الافتراضي منتقي النظام.
- وضع العدسة الحية يستخدم نافذة بحجم الشاشة (`PickerInput.cs`)، لأن المركّب لا يوصل الإدخال إلا لنافذة ظاهرة.

**عقد موحّد للالتقاط:**

```rust
pub trait Sampler: Send {

    fn patch(&mut self, at: Point, size: u32) -> Result<Patch, CaptureError>; // للعدسة
}
```

الاختيار بين التنفيذات يتم وقت التشغيل بحسب النظام ونوع الجلسة، وكل تنفيذ خلف `cfg` خاص بنظامه.

## 5. الواجهة بتقنيات الويب

### 5.1 الهيكل

- **صفحة HTML واحدة** فيها تنقّل داخلي بين الصفحات السبع والإعدادات. لا خادم ولا روابط خارجية.
- **المكونات المشتركة:**
  - `Glass` و`Spine`: الشريط الجانبي القابل للتمدد.
  - `Header`: مع القطّارة العامة.
  - `Sheet` و`Select`: طبقة واحدة فوق الصفحة كما في `Overlay.cs`.
  - `Toast` و`ThemeSwitch` و`Swatch` و`Field` و`Slider` و`Icon`.
- **الأيقونات:** أيقونات Tabler الحالية (36 أيقونة SVG في `desktop/Icons`)، تُستورد كمكونات وتأخذ لون النص الموروث.

### 5.2 الاتجاه والترجمة

- **الاتجاه:** ‏`<html lang="ar" dir="rtl">` افتراضيًا، ويتحول إلى `dir="ltr"` عند اختيار الإنجليزية دون إعادة تحميل.
- **الأصناف المنطقية فقط:** مثل `ms-*` و`me-*` و`ps-*` و`pe-*` و`start-*` و`end-*` و`text-start`. يُمنع استخدام `left` و`right` إلا لعناصر تتبع الشاشة لا القراءة، كمسار السحب في محرّر التدرجات.
- **القيم اللاتينية:** HEX وRGB وغيرهما داخل `<bdi>` أو عنصر بصنف `.ltr` يضبط `unicode-bidi: isolate`، كما في النموذج.
- **الحقول الحرة:** ‏`dir="auto"`، مع إبقاء النص الإرشادي على اليمين حين يكون الحقل فارغًا (انظر 17.3).
- **الترجمة:** ‏`ar.json` هو المصدر و`en.json` ترجمة له، ويُنقل الملف الحالي `Localization.en.json`. فحص في CI يمنع وجود مفتاح بلا ترجمة.

### 5.3 Tailwind CSS 4 وألوان الهوية

تنتقل ألوان `Theme.axaml` إلى `@theme` كمتغيرات، ويعرّف المظهران الداكن والفاتح قيمها:

```css
/* ui/src/app.css */

@custom-variant light (&:where([data-theme=light], [data-theme=light] *));

@theme {
  --font-sans: "Noto Kufi Arabic", "Plus Jakarta Sans", system-ui, sans-serif;
  --font-latin: "Plus Jakarta Sans", "Noto Kufi Arabic", sans-serif;

  --color-brand: #FFF000;          /* Accent */
  --color-brand-hover: #FFF566;    /* AccentHover */
  --color-brand-ink: #111111;      /* AccentInk */
  --color-danger: #FF9E94;

  --radius-card: 20px;
  --radius-pill: 999px;
  --ease-liquid: cubic-bezier(.2, .8, .2, 1);
}

:root {                    /* الداكن: Canvas وRaised وInk وMuted وGlass* من Theme.axaml */
  --canvas: #111111; --raised: #1C1C1A; --ink: #FFFFFF; --muted: #ADADA5;
  --line: rgb(255 255 255 / .14); --glass-tint: rgb(255 255 255 / .07);
  --glass-rim: rgb(255 255 255 / .34); --glass-shade: rgb(0 0 0 / .45);
}
[data-theme="light"] {     /* الفاتح */
  --canvas: #F4F3EE; --raised: #FFFFFF; --ink: #111111; --muted: #5A5A54;
  --line: rgb(17 17 17 / .13); --glass-tint: rgb(255 255 255 / .58);
  --glass-rim: rgb(255 255 255 / 1); --glass-shade: rgb(17 17 17 / .14);

```

- **أصناف مخصصة:** ‏`@utility glass` و`@utility glass-live` و`@utility pill` لتأثيرات تتكرر، ويبقى كل منها في مكان واحد.
- **قاعدة مراجعة الكود:** لا ألوان مكتوبة مباشرة في أصناف المكونات، مثل `bg-[#123456]`. كل لون يأتي من الهوية أو من لون المستخدم.

### 5.4 الخطوط

- الخطان كما هما: Noto Kufi Arabic للعربية وPlus Jakarta Sans للاتينية، مع مقياس الخطوط الموحد من `Ui.cs`.
- **إصلاح لازم:** النسخ التي يولّدها `scripts/fonts.py` من الخط المتغيّر **تفقد نقاط الياء في آخر الكلمة داخل WebKit**، أي تظهر «فولاذى» بدل «فولاذي». النسخة الثابتة الأصلية من الخط نفسه تعمل سليمة. شُخّص ذلك في النموذج (`prototypes/tauri-arabic/screenshots/yeh-probe.png`).
- **المطلوب قبل أي شاشة:**
  1. إما استخدام الملفات الثابتة الأصلية من Google Fonts، أو إصلاح عملية القص في `fonts.py` والتحقق منها في WebKit.
  2. إضافة اختبار لقطة شاشة يتحقق من «ي» في آخر الكلمة بكل وزن.
- **التحميل:** ‏`font-display: block` لملفات محلية صغيرة، وإعلان الأوزان المستخدمة فقط.
- **ملاحظة مفتوحة:** في WebKitGTK ظهر نص الحقول بخط النظام رغم تحديد الخط صراحة. يُحل في المرحلة الأولى، بفحص سمة GTK أو `appearance: none` على الحقول.

### 5.5 الحركة

| التأثير | الحالي | البديل في الويب |
|---|---|---|
| انتقالات الصفحات والقوائم «السائلة» | ‏`Goo` في `Glass.cs` | ‏View Transitions API حيث يدعمها المحرك، وإلا انتقالات CSS على `transform` و`opacity` |
| نوابض باقة اليوم | ‏`PackStage.cs` بنوابض مخمّدة | دالة نابض صغيرة بـ TypeScript تنقل المعادلات نفسها، وتُطبَّق عبر `requestAnimationFrame` على `transform` فقط |
| الظرف الثلاثي الأبعاد | ‏`Matrix4x4` مع `M34` | ‏`perspective` و`transform-style: preserve-3d` و`rotateX`. المعادلات تُنقل كما هي |
| مفتاح المظهر | ‏`ThemeSwitch.cs` برسم بكسلات | مكوّن `<canvas>` ينقل خطة البكسلات والانفجار الحالية كما هي |
| تقليل الحركة | إعداد داخلي | الإعداد الداخلي، مع `prefers-reduced-motion` كقيمة افتراضية |

**قاعدة:** كل حركة مستمرة تكون على `transform` أو `opacity` فقط. لا تُحرَّك الخصائص `width` و`height` و`flex` و`box-shadow` و`filter`. هذا ما رفع الأداء في النموذج.

### 5.6 بديل يبقي المشروع كله بـ Rust

إن رُغب في أن تكون الواجهة نفسها Rust، فالبديل **Leptos** مترجمًا إلى WebAssembly داخل Tauri، مع Tailwind 4 نفسه:
- **ما لا يتغير:** المتصفح يبقى مسؤولًا عن العربية والاتجاه والزجاج، وكل ما في هذه الخطة يبقى صحيحًا عدا لغة المكونات.
- **الثمن:** نظام مكونات أقل نضجًا من Svelte، وزمن ترجمة أطول، وأدوات حركة أقل.

**التوصية:** ‏Svelte مع TypeScript للواجهة. تبقى Rust لكل ما تحت الواجهة.

## 6. التصميم: المحافظة والتطوير

### 6.1 ما يُحافظ عليه حرفيًا

- **الألوان:** الأصفر `#FFF000` والأسود `#111111` في المظهرين.
- **الشريط الجانبي:** لوح زجاج ينمو من حافة النافذة، يتمدد عند المرور فوقه ويُظهر الأسماء (`Controls.cs`).
- **العيّنة:** اللون نفسه من الحافة للحافة، دون أي مادة شفافة فوقه تغيّر لونه، ونصها بلون حبر مقروء من النواة.
- **الإشعارات:** تصعد من الزاوية التي تبدأ منها القراءة، أي أسفل اليمين بالعربية.
- **التميمة:** الأيقونة والعلامة في شريط العنوان.
- **إطار النافذة المخصص:** الشريط يعمل كعنوان، وأزرار النافذة في آخر الصف (`decorations: false` مع مناطق سحب).

### 6.2 قواعد الزجاج المبنية على القياس

قيس في النموذج على شاشة 3072×1728 بمضاعفة ×2 ومعالج Intel UHD 630:

| الإعداد | السكون | التحريك المستمر |
|---|---|---|
| تمويه حي على خمس بطاقات | ~40 إطارًا في الثانية | ~32 |
| تمويه حي على الشريط الجانبي فقط، وبطاقات مُعتّمة | **60 ثابتة** | ~48 |

**القاعدة المعتمدة:**
- **التمويه الحي** (`backdrop-filter`) على سطح أو سطحين فقط: الشريط الجانبي، ونوافذ `Sheet` حين تفتح فوق محتوى متحرك.
- **البطاقات** زجاج مُعتّم: لون شفاف ولمعة علوية وحافة مضيئة. الأضواء خلفها تدرجات ناعمة أصلًا، فلا يغيّر التمويه الصورة. وهذا ما يفعله `Glass.cs` حاليًا أيضًا («Blur is only worth its cost where the pane overlaps other content»).
- **الأضواء الخلفية** تدرجات شعاعية تتحرك بالإزاحة، لا عناصر عليها `filter: blur`.
- **إعداد «زجاج كامل»** اختياري يعيد التمويه الحي لكل البطاقات للأجهزة القوية. يُعرض مع «تقليل الشفافية» في الإعدادات.

### 6.3 تحسينات مقترحة على التصميم

1. **تجاوب حقيقي:**
   - أقل حجم للنافذة 900×640 كما هو.
   - استعلامات الحاوية (`@container`) لتتبدل الشبكات من عمودين إلى عمود حسب عرض البطاقة لا عرض النافذة.
   - الشريط الجانبي ينطوي تلقائيًا تحت عرض معين.
2. **لوحة أوامر** بـ Ctrl+K: بحث موحد في الأدوات واللوحات والألوان والإجراءات، امتدادًا لـ `ProjectSearch.cs`.
3. **سحب وإفلات لترتيب الألوان** في اللوحات. هو مذكور في خارطة الطريق ويسهل كثيرًا في الويب.
4. **محرر OKLCH مرئي** بمنزلقات إدراكية، يظهر فيه حد نطاق sRGB.
5. **حالات فارغة وتحميل** مصممة لكل صفحة بدل المساحات الفارغة.
6. **وضوح التركيز:** حلقة تركيز صفراء موحدة تظهر بلوحة المفاتيح فقط عبر `:focus-visible`.
7. **تباين مضمون:** كل نص فوق لون المستخدم يأخذ حبره من النواة (`ink`). لا يُحسب الحبر في الواجهة.

## 8. مراحل التنفيذ

التقديرات لمطوّر واحد متفرغ. كل مرحلة لها معيار خروج واضح، ولا تبدأ مرحلة قبل تحقيق معيار سابقتها.

### المرحلة 0: التأسيس (أسبوع واحد)

- **العمل:**
  - مساحة عمل Cargo، ونقل `src/` إلى `crates/core` مع بقاء الاختبارات الـ 37 خضراء.
  - هيكل Tauri وVite وSvelte وTailwind 4، وتوليد الأنواع بـ `tauri-specta`.
  - إصلاح الخطوط (5.4) وإضافة اختبار الياء.
  - CI للأنظمة الثلاثة يبني التطبيق الجديد بجوار القديم.
- **معيار الخروج:** نافذة فارغة بالهوية على الأنظمة الثلاثة، والأنواع المولدة تُترجم، والاختبارات خضراء.

### المرحلة 1: الإطار والتخزين (أسبوعان)

- **العمل:**
  - ‏`crates/store` بقراءة `workspace.json` وكتابته، مع اختبارات تقرأ نسخًا حقيقية من كل مخطط سابق.
  - ‏`apply` و`undo` و`redo`.
  - الإطار: الشريط الجانبي، والعنوان، والطبقة العلوية، والإشعارات، ومفتاح المظهر، والإعدادات.
  - الاتجاه والترجمة.
- **معيار الخروج:** التطبيق الجديد يفتح مكتبة حقيقية من النسخة الحالية ويحفظها، ثم تفتحها النسخة الحالية دون فقدان أي حقل. يُتحقق من ذلك باختبار ذهاب وإياب آلي.

### المرحلة 2: الصفحات الأساسية (3 أسابيع)

- **العمل:** ملتقط الألوان (دون القطّارة)، ولوحات الألوان بالشبكة والقائمة والبحث والمفضلة والإجراءات الجماعية والأدوار والاستيراد والتصدير، وفحص التباين مع محاكاة عمى الألوان، والسجل.
- **معيار الخروج:** كل إجراءات هذه الصفحات في README تعمل، مع لقطات مقارنة بالعربية والإنجليزية في المظهرين.

### المرحلة 3: الصور والتدرجات وباقة اليوم (3 أسابيع)

- **العمل:**
  - تحليل الصور: اللصق والسحب، والحدود الحالية، والإلغاء، والدليل بخطوطه، وأخذ لون بكسل.
  - محرّر التدرجات.
  - باقة اليوم مع الظرف الثلاثي الأبعاد والبطاقات والقصاصات والأرشيف وأقفال الهوية، ووضع `--preview-envelope`.
- **معيار الخروج:** اختبار «لا تتقاطع الخطوط» بنسخته الجديدة، والظرف بحركة 60 إطارًا على الجهاز المرجعي، وتقليل الحركة يعمل.

### المرحلة 4: الالتقاط (4 أسابيع، وهي الأعلى خطورة)

- **العمل:** ‏`crates/capture` لـ X11 وWindows وWayland (المنتقي، والعدسة الحية عبر PipeWire، وإضافة GNOME) وmacOS، ونافذة العدسة الشفافة، والالتقاط المتعدد.
- **معيار الخروج:**
  - اختبار X11 الحالي (بكسل معروف خارج النافذة، والإلغاء) يعمل على التطبيق الجديد.
  - اختبار البوابة وPipeWire يعمل.
  - تجربة يدوية على GNOME وKDE وWindows 11 وmacOS موثقة.

### المرحلة 5: خدمات النظام (أسبوعان)

- **العمل:** الاختصار العام بالإبلاغ عن التعارض، وقائمة النظام، والمثيل الواحد، والنسخ الاحتياطي والاستعادة بسجلها، وتقرير الدعم، وحفظ حالة النافذة.
- **معيار الخروج:** اختبارات الاختصارات والاستعادة المنقطعة تعمل، ومراجعة أن تقرير الدعم لا يحوي ألوانًا ولا مسارات.

### المرحلة 6: الجودة والتوزيع (أسبوعان)

- **العمل:** اختبارات WebDriver، وميزانيات الأداء في CI، ومراجعة إمكانية الوصول، والحزم (القسم 14)، والتوقيع، وقناة التحديث الموقعة.
- **معيار الخروج:** كل معايير القسمين 10 و11 محققة، وحزم الأنظمة الثلاثة تُثبّت وتُرقّى من النسخة الحالية.

### المرحلة 7: بيتا والتشغيل المتوازي (3 إلى 4 أسابيع)

- **العمل:**
  - إصدار بيتا 2.0 بجوار 1.x، كلاهما يقرأ المكتبة نفسها ولا يعملان معًا بسبب القفل.
  - جمع البلاغات، ثم إصدار 2.0 النهائي، ثم نقل `desktop/` إلى `legacy/` ثم حذفه بعد إصدارين.
- **معيار الخروج:** لا بلاغات فقدان بيانات، ولا تراجع في الوظائف عن 1.2.0.

## 9. توافق البيانات والانتقال الآمن

1. **لا تغيير في الصيغ خلال 2.0.** يقرأ التطبيق الجديد ويكتب `workspace.json` بالمخطط 2 نفسه، و`daily_palette_state.json` بالنسخة نفسها، وحزم النسخ الاحتياطي نفسها.
2. **الحقول المجهولة تُحفظ.** يحتفظ Rust بأي حقل لا يعرفه، عبر `#[serde(flatten)] extra: Map`، فلا يحذف إعدادات أضافتها نسخة أحدث أو أقدم.
3. **اختبار ذهاب وإياب في CI:** ملفات حقيقية من الإصدارات 0.4 و1.0 و1.1 و1.2. يقرؤها التطبيق الجديد ويكتبها، ثم يقرؤها كود C# القديم في الاختبار نفسه، ويُقارن الناتج حقلًا بحقل.
4. **نسخة احتياطية تلقائية عند أول تشغيل** للإصدار 2.0 باسم `workspace.v1-backup.json` قبل أي كتابة.
5. **قفل واحد** يمنع تشغيل 1.x و2.0 معًا على المكتبة نفسها.
6. **إن احتاج المخطط تغييرًا لاحقًا:** يُرفع الرقم إلى 3، مع ترحيل في Rust واختبار. النسخ الأقدم ترفض المخطط الأحدث كما يحدث الآن.

## 10. معايير الأمان

| المعيار | التطبيق |
|---|---|
| لا محتوى خارجي | الواجهة كلها من الحزمة المحلية، ولا `http` في الإنتاج. أي رابط خارجي يُفتح في متصفح النظام عبر `opener` بعد التحقق من القائمة المسموحة |
| سياسة CSP صارمة | ‏`default-src 'self'; img-src 'self' blob: data:; style-src 'self'; script-src 'self'; connect-src ipc: http://ipc.localhost`، ولا `unsafe-eval` ولا `unsafe-inline` في الإنتاج |
| صلاحيات بأقل قدر | ملفات `capabilities/` تمنح كل نافذة الأوامر التي تحتاجها فقط. نافذة العدسة لا تصل إلى أوامر المكتبة. لا تُضاف إضافات `shell` ولا `fs` العامة، والوصول للملفات عبر أوامر خاصة بمسارات محددة |
| التحقق من المدخلات في Rust | كل أمر يتحقق من مدخلاته بأنواع صارمة (`Hex` يُبنى فقط من `#RRGGBB` صحيح)، ولا يثق بالواجهة |
| حدود الأحجام | تبقى كما هي: الصورة 32 ميغابايت و40 ميغابكسل، واستيراد JSON ‏2 ميغابايت، والنسخة الاحتياطية 16 ميغابايت. يُفحص الحجم قبل القراءة |
| الخصوصية | لا تحليلات ولا حسابات ولا شبكة. سجل الدعم اختياري ومحدود، ولا يحوي ألوانًا ولا صورًا ولا مسارات ولا نص الحافظة |
| الالتقاط بإذن المستخدم | على Wayland عبر البوابات فقط. وضع مشاركة الشاشة اختياري وظاهر، وينتهي بإغلاق التطبيق |
| سلسلة التوريد | ملفا `Cargo.lock` و`pnpm-lock.yaml` ملتزمان. ‏`cargo-deny` يفحص التراخيص والثغرات والمصادر، و`pnpm audit` يعمل في CI. لا اعتماديات من مصادر غير الرسمية |
| التوقيع | ‏Authenticode لويندوز، وDeveloper ID مع التوثيق لماك، وتوقيع حزم لينكس. بيانات الاعتماد لا تُلتزم أبدًا، كما هو الحال الآن |
| التحديث | ‏`tauri-plugin-updater` يقبل فقط حزمًا موقعة بمفتاح المشروع وتحمل رقم الإصدار المعلن (`requireSignedVersion`). لا يتصل إلا حين يطلب المستخدم التحقق (`docs/release.md`) |
| الكود غير الآمن | ‏`unsafe` محصور في `crates/capture` لاستدعاءات النظام، مع تعليق لكل كتلة يشرح سبب سلامتها، ويُراجَع في كل تغيير |

## 11. معايير الأداء

**الجهاز المرجعي:** لابتوب بمعالج Intel UHD 630، وشاشة 3072×1728 بمضاعفة ×2، وWayland. هذا جهاز التطوير الحالي، وهو حالة صعبة نسبيًا.

| المقياس | الهدف | طريقة القياس |
|---|---|---|
| زمن الإقلاع حتى أول عرض | أقل من 800 ميلي ثانية | قياس تلقائي في CI بعد تحميل الصفحة |
| إطارات السكون | 60 ثابتة ولا إطار فوق 25 ميلي ثانية | وضع `PICKERHUB_BENCH` الموجود في النموذج |
| التفاعل المستمر (شريط اللون، والسحب) | 50 إطارًا على الأقل، وp95 أقل من 25 ميلي ثانية | الوضع نفسه |
| استجابة الالتقاط | من النقر إلى ظهور اللون أقل من 100 ميلي ثانية | قياس داخلي في سجل التشخيص |
| تحليل صورة 1920×1080 | أقل من 60 ميلي ثانية في Rust | اختبار أداء بـ `criterion` |
| الحجم | ملف تنفيذي أقل من 15 ميغابايت، وحزمة أقل من 25 ميغابايت | فحص في CI يفشل عند التجاوز |
| الذاكرة | أقل من 200 ميغابايت للعمليتين بعد ساعة استخدام | قياس يدوي قبل كل إصدار |

**قواعد تحقق هذه الأرقام:**
- استدعاء Rust واحد في كل إطار على الأكثر، يُجدول عبر `requestAnimationFrame`.
- تحديث العناصر في مكانها، دون إعادة بناء القوائم.
- عرض القوائم الطويلة على صفحات أو بشكل افتراضي، كالحد الحالي 48 لونًا في الصفحة.
- ذاكرة تخزين مؤقت لأوصاف الألوان في Rust، كالحالية بحجم 512.
- الحركة على `transform` و`opacity` فقط، والتمويه الحي على سطح أو سطحين.
- متغيرات CSS التي تتغير كثيرًا تُضبط على العناصر التي تستخدمها، لا على جذر الصفحة.
- الصور تُصغَّر في Rust قبل وصولها للواجهة، كالحد الحالي 768 بكسلًا.

## 12. قابلية التوسع وسهولة الصيانة

- **حدود واضحة بين الحزم:**
  - `core` لا يعرف Tauri ولا الملفات.
  - `store` لا يعرف الواجهة.
  - `capture` لا يعرف المكتبة.
  - تطبيق Tauri هو الوحيد الذي يجمعها.

  هذا يسمح باستخدام النواة نفسها في سطر أوامر أو نسخة ويب لاحقًا.
- **عقد اتصال مولّد:** أنواع TypeScript تُولّد من Rust في كل بناء، وCI يفشل إن اختلفت.
- **المعايير:**
  - Rust: ‏`cargo fmt` و`cargo clippy -D warnings`، وتوثيق كل دالة عامة.
  - الواجهة: ‏`prettier` مع إضافة Tailwind لترتيب الأصناف، و`eslint` و`svelte-check` و`tsc --noEmit` في الوضع الصارم.
- **الترجمة:** مفاتيح ثابتة، وفحص الترجمات الناقصة، ولا نصوص مكتوبة مباشرة في المكونات.
- **سجل قرارات معمارية** في `docs/adr/`، يكتب سبب كل قرار كبير. أول قرار هو هذه الخطة.
- **الإصدارات:**
  - نظام SemVer، و`CHANGELOG.md` كما هو الآن.
  - مخطط البيانات له رقم مستقل عن رقم الإصدار.
- **تتبع الأخطاء:** رموز أخطاء ثابتة تُعرض في تقرير الدعم، فيُعرف مصدر البلاغ دون إرسال بيانات المستخدم.

## 14. البناء والتوزيع والتحديث

| النظام | الحزم | ملاحظات |
|---|---|---|
| Linux | ‏`.deb` و`.rpm` و`.AppImage` | تعتمد على WebKitGTK 4.1 من النظام. AppImage تضمّن ما تحتاجه. لاحقًا Flathub |

- **التحديث:** ‏`tauri-plugin-updater` بملف `latest.json` موقّع على إصدارات GitHub، ولا يُفعّل إلا بعد توفر التوقيع.
- **سطر الأوامر:** يُحافظ على `--self-test` و`--preview-envelope`.

4. **ثيمات دلالية كاملة:** توليد سلّم ألوان (50 إلى 950) لكل لون بقواعد OKLCH مع ضمان التباين، امتدادًا لباقة اليوم.

### متوسطة المدى
5. **سطر أوامر `pickerhub`** يستخدم `crates/core` لاستخراج ألوان صورة أو فحص تباين في سكربتات المصممين وCI.
6. **نسخة ويب** من الأدوات التي لا تحتاج التقاط الشاشة، بترجمة النواة إلى WebAssembly ومشاركة مكونات الواجهة نفسها.
7. **إضافة لـ Figma** تستخدم النواة نفسها عبر WebAssembly لتسمية الألوان بالعربية وفحص التباين داخل Figma.
8. **مزامنة اختيارية مشفرة من الطرفين** بين الأجهزة، بملف في مجلد يختاره المستخدم (مثل Syncthing أو iCloud Drive) دون خادم خاص.

### بعيدة المدى
9. **تطبيق جوال** عبر دعم Tauri 2 للهاتف: لوحات ومكتبة وتحليل صور من الكاميرا.
10. **متاجر التوزيع:** ‏Flathub وwinget وHomebrew وMicrosoft Store، مع تحديث موقع.
11. **لغات واجهة إضافية:** الفارسية والأردية تستفيدان مباشرة من بنية RTL، ثم الفرنسية والتركية.
12. **إمكانية وصول متقدمة:** محاكاة ضعف البصر والتباين المنخفض، ووصف صوتي للألوان.

## 17. ملحق: نتائج النماذج التجريبية

### 17.1 مقارنة النموذجين

| | iced 0.14 (Rust أصلية) | Tauri 2 |
|---|---|---|
| الملف التنفيذي | 10.4 ميغابايت | **4.9 ميغابايت** |
| التشكيل العربي والخلط مع الإنجليزية | سليم | سليم |
| قلب الواجهة لليمين | ترتيب يدوي في كل صف | ‏`dir="rtl"` واحد |
| المحاذاة لليمين | خلل في المكتبة، احتاج تجاوزًا | سليم |
| التحديد في حقل عربي | لا يظهر، واحتاج تعديل كود iced | سليم دون تعديل |
| النقاط تحت الحروف في الحقل | تُقص، واحتاجت ارتفاع سطر أكبر | سليمة |
| التفاف فقرة طويلة | تتجاوز حافة البطاقة دون حل | سليم |
| تمويه حقيقي | غير متاح دون shaders | ‏`backdrop-filter` |
| سلاسة السكون على الجهاز المرجعي | لم تُقَس | 60 ثابتة بعد التحسين |

### 17.2 أرقام سلاسة Tauri على الجهاز المرجعي

| الإعداد | السكون | تحريك اللون في كل إطار |
|---|---|---|
| البداية (تمويه على 5 بطاقات، وأضواء بـ `filter: blur`) | 28 إلى 40 | 24 إلى 32 |
| أضواء بتدرجات شعاعية | 40 إلى 59 | ~32 |
| تمويه حي على الشريط الجانبي فقط | **60** | ~48 |
| على كرت NVIDIA مع تمويه كامل | ~48 إلى 52 | ~41 إلى 45 |

على NVIDIA يكاد التمويه الكامل يكون مجانيًا، لكن السقف أقل بسبب نسخ كل إطار إلى معالج Intel المتصل بالشاشة، وهذا من تصميم أجهزة Optimus.

### 17.3 أخطاء اكتُشفت وأُصلحت في نموذج Tauri

1. **ياء آخر الكلمة بلا نقاط:** السبب ملف الخط المقصوص، وأُصلح بالنسخة الثابتة الأصلية.
2. **لقطة الشاشة لا تُظهر التحديد:** خيار `INCLUDE_SELECTION_HIGHLIGHTING` في WebKit.
3. **النص الإرشادي في حقل `dir="auto"` الفارغ يظهر على اليسار:** أُصلح بقاعدة `:placeholder-shown { direction: rtl }`.
4. **تداخل بطاقة التناغم مع البطاقات فوقها في النوافذ القصيرة:** أُصلح بجعل منطقة المحتوى قابلة للتمرير.

لتشغيل النموذج والقياس:

```bash
prototypes/tauri-arabic/target/release/pickerhub-tauri
PICKERHUB_BENCH=1 prototypes/tauri-arabic/target/release/pickerhub-tauri
prototypes/tauri-arabic/run-nvidia.sh all
```
